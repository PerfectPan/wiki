# 大模型 101

## 问题

用 Claude Code / Codex / OpenCode 写代码时，用量数字、cache、套餐、Responses/Messages 这些词分别是什么？哪些值得记、哪些只是插头？

## 简答

先分清三层：**计费单位（token/cache）**、**执行循环（模型出 tool call，本地干活）**、**HTTP 协议形状（Completions / Messages / Responses）**。前两层决定账单和能力体感；第三层主要影响框架怎么接模型。

## 综合结论

### 1. 用量：先会读分项

- Token 是计费原子；`1M = 100 万`，`1B = 10 亿`，`100M = 1 亿`。
- 报表至少看四项：input、cache write、cache read、output。Coding agent 的 **total 往往被 cache read 撑到几亿～几十亿/周**，但单价低。
- `ccusage --compact` 可能藏掉 cache；要以非 compact 或 `--json` 为准。详见 [[Token 与计费口径]]。
- Prompt Cache 与推理引擎内部的 KV Cache 不是同一层概念，边界见 [[KV Cache 与请求缓存的边界]]。

### 2. 写代码：本质是 tool loop

```text
while 未完成:
  调模型（带 tools 定义 + 历史）
  若返回 tool_calls / tool_use:
      本地并行或串行执行（读改跑）
      把结果写回历史
  否则输出最终回复并结束
```

- 模型决定「下一步调哪个工具」；**读文件、改仓库、跑测试在你机器上**。
- 一轮里可以点名多个工具（并行）；模型会 **停住等结果**，不会在没返回时继续瞎写结论。
- 这就是 [[Code Agent]] 相对纯聊天的核心差别。循环控制边界另见 [[Agent 循环工作流的控制边界]]。

### 3. 协议：三种插头，一种循环

| 插头 | 一句话 | 常见消费者 |
| --- | --- | --- |
| [[Chat Completions]] | 江湖通用语 | OpenCode、Cline、多数兼容 API |
| [[Anthropic Messages API]] | Claude 原生块协议 | Claude Code |
| [[Responses API]] | OpenAI agent 资源 + item 列表 | Codex 新链路 |

选型见 [[LLM API 协议选型]]。  
**常见误解**：以为 Responses 才「支持多步」。多步来自客户端循环；Responses 只是把多类型块和续聊标准化。

### 4. 套餐 vs API

- **订阅 Coding Plan**：固定月费 + 5h/周额度（prompt 或 credits），适合中等用量；额度与计量方式会改版（如 z.ai V2 prompt → V3 credits）。
- **API 按量**：无封顶，单价 × 真实分项；重度并行多 agent 时账单可到每周数千美元量级（顶配 Claude/OpenAI），也可降到 DeepSeek Flash 的数十美元量级（能力与稳定性另论）。
- 同一套本地 total tokens，换模型只变「乘哪个价目表」，不变「你烧了多少上下文」。

### 5. 价格心智（易过期，只记结构）

对话整理时点（2026-08 前后）的粗结构，**以官网为准**：

```text
贵 → 便宜（同为旗舰/编码向 API）:
Fable/Opus 档 ≈ GPT-5.6-sol 档
  > Kimi K3 / GLM-5.2 / Terra / K2.7 Code
  >> DeepSeek V4-Pro / V4-Flash
```

- DeepSeek-V4-Flash-0731（2026-07-31 API 正式 beta）主打 agent 后训练，官方榜接近部分闭源，且单价极低；接 agent 时仍要在自己的 harness 里验收，不宜只看自家榜。
- Cache 极高时，**cache hit 单价**和 **output 单价**往往比「标价 input」更能决定周账单。
