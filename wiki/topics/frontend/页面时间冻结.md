# 页面时间冻结

## 摘要

编辑要求目标稳定：选中、检视、改值都假设光标下的对象持续存在。而"目标不稳定"有两种失败模式：**在动**（动画、过渡、hover 态、定时消失——对象还在，但抓不住某个瞬间）和**被换掉**（框架重建 DOM，旧对象死了，新对象不认识你）。前者冻结时间，后者重新绑定。本页两种都讲，重点在冻结；两者互补，拥有预览容器的产品通常两个都要。参考实现是 [[Voila]] 扩展中 889 字节的 `freeze.js`。

## 机制：三个时间原语

页面里的动效最终都落在三个函数上：

- `requestAnimationFrame`：CSS 之外的逐帧动画、大部分动画库
- `setTimeout`：延迟触发、自动关闭、过渡结束回调
- `setInterval`：轮播、轮询、跑马灯

替换这三个函数，就拿到了页面时间的控制权。实现维护一个速度因子 `rate`（默认 `1`）：

| rate | 行为 |
| --- | --- |
| `1` | 直接透传原函数，零开销 |
| `0` | **冻结**：rAF 回调压入队列不执行；setTimeout 改为每 100ms 自旋重试；setInterval 直接跳过 |
| `0 < rate < 1` | **慢放**：setTimeout 延时除以 rate（拉长）；rAF 每 `max(1, round(1/rate))` 帧才放行一次 |

解冻时把冻结期间积压的 rAF 回调一次性 flush，动画从暂停处继续，而不是丢帧跳跃。

参考实现骨架（据 `freeze.js` 反混淆整理）：

```js
let rate = 1;
const rawRaf = window.requestAnimationFrame.bind(window);
const rawTimeout = window.setTimeout.bind(window);
const rawInterval = window.setInterval.bind(window);
const pending = [];
const stride = () => Math.max(1, Math.round(1 / rate));

window.requestAnimationFrame = (cb) => {
  if (rate === 1) return rawRaf(cb);              // 常态零开销
  if (rate === 0) return pending.push(cb), -1;    // 冻结：只入队
  let n = 0;                                       // 慢放：跳帧
  const tick = (t) => {
    if (rate === 0) return void pending.push(cb);
    ++n >= stride() ? cb(t) : rawRaf(tick);
  };
  return rawRaf(tick);
};

window.setTimeout = (fn, ms, ...args) => {
  if (typeof fn !== 'function') return rawTimeout(fn, ms);
  const d = (rate > 0 && rate < 1) ? ms / rate : ms;
  return rawTimeout(function self() {
    if (rate === 0) return void rawTimeout(self, 100);  // 冻结时自旋等待
    fn(...args);
  }, d);
};

window.setInterval = (fn, ms, ...args) => {
  if (typeof fn !== 'function') return rawInterval(fn, ms);
  let n = 0;
  return rawInterval(() => {
    if (rate !== 0 && ++n >= stride()) { n = 0; fn(...args); }
  }, ms);
};
```

## 落地约束

**必须在页面自己的 JS 世界里替换。** 扩展的隔离世界（isolated world）拿到的是另一份 global，改不到页面的 `window`。Voila 在 manifest 里给这个脚本单独声明 `"world": "MAIN"`。

**必须赶在页面脚本之前。** 任何库若早于替换执行、并把原始 `requestAnimationFrame` 存进自己的闭包，之后就绕过了劫持。注入时机是 `document_start`，不是 `document_idle`。

**需要一条跨世界的控制通道。** MAIN world 的脚本和扩展 UI 不共享内存。Voila 用 DOM 当信道：UI 侧把速度因子写到 `document.documentElement.dataset`，再派发自定义事件通知 MAIN world 读取。

**幂等守卫。** 用一个 global 标记避免重复注入导致多层包装（每层都会再套一次跳帧逻辑）。

## 边界与代价

- **管不到纯 CSS 动效。** `transition` 和 `animation` 由合成器驱动，不经过 JS。要停这部分得另外注入 `animation-play-state: paused` 之类的覆盖样式。
- **对页面有侵入。** 替换全局函数是有副作用的操作；常态（`rate === 1`）必须透传原函数，不给正常浏览加开销。
- **冻结是忙等。** setTimeout 走 100ms 自旋，长时间冻结会积压一批待触发回调，解冻瞬间可能集中执行。

## 它解锁了什么

冻结本身只是"让页面停下来好检视"。真正的收益是**逐帧调动画**：能停住、能慢放、能定位到动画的任意时刻，才谈得上在 GUI 里编排关键帧。Voila 的关键帧编辑支持 `translate` / `scale` / `rotate` / `opacity` / `width` / `height` / `border-radius` / `background-color` / `color` / `border-color` / `filter`——时间冻结和关键帧编辑是同一套组合拳，不是两个功能。

## 另一种失败模式：目标被换掉

上面的冻结解决的是"目标在动"。但冻结救不了第二种情况：框架把元素**重建**了——Antd Button 改 `type` 时内部走 `Wave` 分支重建 DOM，旧引用失效，工具栏失去依附。时间没停也没用，因为问题不是动，而是对象换了。只能接受元素会变、变了再重新绑定。

这类问题的通用解法是一条五步链，每一步对应一个具体问题（以下为模式总结，非任何产品的实现）：

1. **`ResizeObserver` 监听容器**——重建必然引起布局变化，RO 在布局后、绘制前触发，且自带批量合并。选 RO 而非 `MutationObserver`，因为关心的是"视觉位置变了"，不是"DOM 结构变了"。
2. **`requestAnimationFrame` 等一帧**——RO 触发时新子树可能还没完成布局，等一帧确保新元素已挂载且有几何信息。
3. **检查 `isConnected`**——旧引用可能已被移出文档；`isConnected === false` 才需要重绑，否则什么都不做。
4. **用稳定标记属性 `querySelector` 重绑**——框架重建后是全新对象，没有对象级身份。前提是选中时给元素打过稳定标记（如 `data-xxx-id`），重建不丢这个属性才能找回来。
5. **重发坐标**——工具栏和高亮按屏幕坐标定位，新元素位置可能变了，必须重新计算并广播。

这条链的前提是**能往元素上打稳定标记**（拥有预览容器的渲染权，或与框架协作）。标记打不上，第四步就断了。

最小实现（示意代码，非真实项目源码）：

```js
const container = document.querySelector('#preview-root'); // 稳定的外层容器
let tracked = null;

function track(el) {
  el.dataset.editId = crypto.randomUUID(); // ① 选中时打稳定标记
  tracked = el;
}

const observer = new ResizeObserver(() => {
  requestAnimationFrame(() => {                              // ② 等新子树布局完成
    if (tracked?.isConnected) return;                        // ③ 旧引用还在，无需重绑
    const next = container.querySelector(
      `[data-edit-id="${tracked.dataset.editId}"]`,
    );
    if (!next) return;                                       // ④ 标记也丢了，放弃
    tracked = next;
    emitPosition(next.getBoundingClientRect());              // ⑤ 重发坐标
  });
});
observer.observe(container);
```

两个注意点：

- **RO 有盲区**：它只在容器**尺寸**变化时触发。如果重建是尺寸中性的（同样大小的按钮换了 DOM），RO 不响，需要 `MutationObserver` 监听子树变化兜底。
- **标记必须能活过重建**：React 重渲染时，运行时 `setAttribute` 打上去的 `data-*` 可能被丢掉；标记要写在框架认识的 props 里，或接受"丢了就放弃"。Voila 的 `Qm`（`Xm.get(e)?.isConnected`）是同一思路的对象缓存版——不查 DOM，直接验旧引用死活，但同样解决不了"重建后新对象是谁"的问题。

两种路线的选择：

| | 主动冻结 | 被动追踪 |
| --- | --- | --- |
| 侵入性 | 高，替换页面全局函数 | 低，只在自己这侧观察 |
| 覆盖面 | 能停住所有 JS 驱动的动效 | 只处理"元素被替换"这一种症状 |
| 前提 | 能在页面脚本之前注入 MAIN world | 元素有稳定标记可供重新查找 |
| 额外收益 | 解锁逐帧动画编辑 | 无 |

对拥有预览容器的产品（自己的 iframe 里跑用户产物），注入成本很低，两者可以叠加：冻结解决"动着改不了"，重绑解决"组件重建后丢引用"。
