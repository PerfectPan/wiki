# Awesome 资源索引的收录与分级

新增、更新 awesome / curated list 类索引，或调整条目分级时使用本文件。适用于工具、代码库、组件、服务、参考站、课程等资源；按资源所属领域查找现有索引，不把不同领域都塞进同一页。页面结构与 frontmatter 遵循 `SCHEMA.md` 的收录页约定。

## 收录前核对

- 用途：它具体解决什么问题，谁会在什么情况下用到它？
- 使用方式：需要安装、部署、调用服务，还是阅读学习？采用它需要哪些条件？
- 使用限制：按对象检查实际相关的要求，不套用其他领域的检查项。例如代码库看运行环境与依赖，在线服务看费用与数据访问，学习资料看适用读者与内容时效。
- 使用权利：需要复制、修改或分发时核对许可与署名；收费或托管资源核对使用条款。不能默认公开可见就能任意复用。
- 证据：阅读与用途相关的具体文档、示例或内容，记录来源、分级理由和未验证项；区分作者说明、自己的判断与实际测试结果。

## 分级

| 档 | 判断依据 |
| --- | --- |
| 推荐 | 用途明确，有充分材料支持其使用或学习价值；关键使用条件已核对。 |
| 可参考 | 有具体价值，但证据、适用范围或使用条件仍有需要核实的部分。 |
| 偏薄 | 材料不足以指导采用；仅在能说明具体问题、有教学价值时作为反例收录，否则留在原始资料中。 |

按该资源的实际用途分级。阅读资料不要求像代码库一样做运行测试；软件也不能只因文档写得好就称为经过实测。分级反映当前证据，不代表适用于所有项目。

## 更新索引

把评审记录放进该对象的 `raw/sources/` 素材，在索引对应分级下添加一行用途与来源，并在 PR 中说明分级理由。已有领域知识页可以作为判断依据，操作步骤仍在 skill 中维护。

只有链接、热度或营销介绍而缺少具体内容的候选，先保存在 `raw/sources/`；未评审名单也放在那里，不把对象名单写进技能。对象本身值得解释时建 topic；需要比较选择时建 comparison；不要为收录步骤另建 synthesis。
