# Awesome 资源索引的收录与分级

新增、更新 awesome / curated list 类索引，或调整条目分级时使用本文件。适用于工具、代码库、组件、服务、参考站、课程等资源；按资源所属领域查找现有索引，不把不同领域都塞进同一页。页面结构与 frontmatter 遵循 `SCHEMA.md` 的收录页约定。

## 按现有 Awesome 选择专属标准

先用本文件的通用标准，再读目标索引对应的参考文件。专属标准补充通用标准，仍使用同一套三档分级。

| 现有索引 | 专属标准 |
| --- | --- |
| `wiki/topics/frontend/awesome-component-libraries.md` | [component-library-criteria.md](component-library-criteria.md) |
| `wiki/topics/ai/awesome-agent-skills.md` | [agent-skill-criteria.md](agent-skill-criteria.md) |

一个 awesome 索引维护一份专属标准，不按全部 Wiki 分类预建规则。新增 awesome 索引前，先与用户讨论收录范围和专属标准；确定后再创建索引、对应参考文件，并更新此表。维护现有索引时直接沿用已确定的标准，无需重复讨论。

只检查与收录用途有关的项目。阅读资料按学习价值判断，实际接入的软件则要核对会影响使用的条件；无法核对时说明缺口，不把未实测写成实测。

## 通用标准

- 用途：它具体解决什么问题，谁会在什么情况下用到它？
- 使用方式：需要安装、部署、调用服务，还是阅读学习？采用它需要哪些条件？
- 使用限制：按对象检查实际相关的要求，不套用其他领域的检查项。例如代码库看运行环境与依赖，在线服务看费用与数据访问，学习资料看适用读者与内容时效。
- 使用权利：需要复制、修改或分发时核对许可与署名；收费或托管资源核对使用条款。不能默认公开可见就能任意复用。
- 证据：阅读与用途相关的具体文档、示例或内容，记录来源、分级理由和未验证项；区分作者说明、自己的判断与实际测试结果。

## 分级

| 档 | 判断依据 |
| --- | --- |
| 推荐 | 用途明确，有充分材料支持其使用或学习价值；关键使用条件已核对。 |
| 可参考 | 有具体价值，但证据、适用范围或使用条件仍有需要核实的部分。 |
| 偏薄 | 材料不足以指导采用；仅在能说明具体问题、有教学价值时作为反例收录，否则留在原始资料中。 |

按该资源的实际用途分级。阅读资料不要求像代码库一样做运行测试；软件也不能只因文档写得好就称为经过实测。分级反映当前证据，不代表适用于所有项目。

## 更新索引与素材保存

一两句话能够说明用途、分级和主要限制时，直接在索引中收录并链接来源，`source_refs` 与 `resource` 可以只写外部 URL，不另外创建 raw 文件。需要解释分级理由时，在条目或 PR 中简要说明即可。

只有存在值得单独保存的原文摘录、多来源分析、源码阅读或验证记录时，才写入该对象的 `raw/sources/` 素材，并从条目链接过去。通用与专属检查用于帮助判断，不要求把每项检查都写成评审报告。

没有合适的现有索引时，按前面的约定与用户讨论是否新建；不要因此自动生成 raw 评审或待评审名单。证据不足或过时的候选不收录，只有资料本身有保存价值或用户明确要求跟进时才保留必要记录。

对象本身值得解释时建 topic，需要比较选择时建 comparison；不要为收录步骤另建 synthesis。已有领域知识页可作为判断依据，操作步骤仍在 skill 中维护。
