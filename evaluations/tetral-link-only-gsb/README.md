# 只给链接：三组 Wiki 整理实验

本轮模拟日常把链接交给 Wiki agent 的用法。共同任务全文是：

> https://tetral.ai/blog/the-next-scaling-problem/
> 整理到 wiki。

三种流程为 GLM 5.3 独立整理、GLM 5.3 分析与审阅加 Gemini 3.8 Flash 写作、Gemini 3.8 Flash 独立整理，均通过 agent-room 执行。候选 D/E/F 在生成前重新随机分配，与上一轮 A/B/C 没有对应关系，模型对应表待评分后揭晓。

## 这次交给模型决定什么

页面标题、类型、路径、数量、章节、表格、篇幅，以及是否更新已有 Agent Harness 页面，都由各组根据仓库现有规则决定。来源由各组从 URL 自行抓取。

Wiki 基线统一为 `e595104eaf5135287bf282553b87a14a71dd8c03`。仓库的 `AGENTS.md`、`SCHEMA.md`、ingest skill 与原有页面保持原样，因此仓库自身的模板仍可能影响结果。本轮撤掉的是上一轮主持人额外加入的写作要求和指定页面，不修改仓库规则。

[task.txt](task.txt) 是任务原文；[room-prompts.md](room-prompts.md) 公开房间角色与操作边界的完整附加提示词。客户端本身的系统提示和本机配置沿用原有环境。

## 实验边界

- 每组使用新的会话和独立工作区，未提供先前实验的原文、成稿或反馈。
- 单模型组自行完成任务；协作组由 GLM 交接给 Gemini，GLM 审阅，必要时集中返修一次。
- 主持人的运行介入如有发生，会在这里记录；不向某一组补充写作答案。
- 协作组分析者交接后曾在当前回合内等待，阻塞串行房间的写作者。主持人提醒其结束本回合、等待再次唤醒，未提供内容意见；原文见附加提示词记录。
- 各流程使用实际客户端适配器，协作组的调用次数和上下文不同。这是实际使用流程的比较，并非等计算预算的模型能力测试。
- 每种流程只运行一次、只使用这一篇文章，尚不能证明其他来源上的稳定表现。
- 本 PR 存放实验档案，尚未采用到正式知识页。旧实验 PR #93 保留作对照。
