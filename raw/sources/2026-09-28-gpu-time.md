## 官网内容（提取正文）

gpu-time 是一个跑在浏览器本地的小型神经模型，把自然语言时间表达转成具体日期、时间段和 RFC 5545 重复规则；输入不会发到服务器。演示中 "book dinner for October 2 at eight pm" 相对 2026-09-27 解析出 "Fri, Oct 2, 2026 8:00 PM"，并附不确定性提示。

官网给出的示例分类：Day or Date、Clock Time、Repeats、How Long。示例覆盖：

- A reminder: tomorrow at 9am
- Dinner: book dinner for October 2 at eight pm
- Standup: every weekday at nine am
- Overnight shift: Friday at 10pm until Saturday at 2am
- A trip: from Sep 4 through September 8
- Payday: the last Friday of each month
- Two-week cycle: every other Friday at noon
- A timer: in 20 minutes for half an hour

开发用法示例：

```js
const { occurrences, rrules } = await parse("Every Monday from 8pm to 10pm", {
  reference: "2026-09-10T12:00:00+06:00",
  timeZone: "Asia/Dhaka",
});
```

官网 "Inside the Model" 一节写 "Words to scores to dates, in 24,761 parameters"。注意：这个数字与仓库 MODEL_CARD.md 声明的 38,745 参数不一致（见下），官网文案疑似停留在早期 checkpoint。

## 仓库结构

```
packages/core       可发布的浏览器包：tokenizer、模型推理（CPU/WGSL kernel）、编译器、日历解析器
packages/training   语料生成、PyTorch 训练、评测、导出、provenance（Python/uv）
packages/benchmark  体积、浏览器性能、与 chrono/compromise/later/Recognizers/rrule 的对比
apps/website        项目站与交互 demo（Astro）
video               讲解视频的脚本与渲染管线
```

`packages/core/src` 关键文件：`calendar.ts`、`clock.ts`、`compile.ts`（编译预测角色到 Schedule，约 2000 行）、`lexicon.ts`（月份名单，只给编译器用）、`model/cpu.ts`（hiddenSize 32、两层门控 scan、CRF 转移矩阵、Viterbi）、`model/gpu.ts` + `kernel.wgsl`（WebGPU 内核，构建期把模型常量拼进 shader 并内联进 JS bundle，`.wgsl` 不随包发布）、`model/weights.gen.ts`（导出的 6-bit 量化权重）、`languages/en.ts`、`languages/es.ts`。

## API（README）

`parse(text, context)` 接受 `{ reference, timeZone, limit }`，返回 `{ occurrences, rrules, diagnostics, truncated, backend, timings }`；`parseMany` 批量；`defineParser(options)` 返回可复用实例（显式 backend + `dispose()`）。`spans` 给出每个答案来自原文的字符偏移。没有公开 AST 或 token 标签输出。未知时区直接拒绝调用，不静默回退。

## 模型与架构（architecture.md + MODEL_CARD.md）

发布的模型（checkpoint `runs/shorthand/epoch-39`）：

- 38,745 参数，两层 scan，580 行 sparse embedding，hidden size 32（cpu.ts 中 `hiddenSize = 32`）
- 35 个语义角色（40 slots，5 保留）：小时、分钟、meridiem、星期、月份、序数、年份、数量与单位、重复标记、范围分隔符、边界、例外、filler 等；`CLOCK_OFFSET` 角色区分半点/一刻钟运算
- 40×40 CRF 转移矩阵（1,600 参数），CPU 上对所有 backend 做 Viterbi 序列解码
- 独立的边界分数把输入切成多个独立表达（阈值由 `calibrate.py` 在 dev split 上拟合）
- 权重 6-bit 对称 per-tensor 量化 + f32 中间值；权重打包 22,501 Brotli 字节，整个 npm 包 45,561 Brotli 字节，发布上限 50,000 字节

关键设计：

- **模型无词表**。tokenizer 只记录字符形状、长度桶、首尾字符类、小写拼写 8-bit hash、辅音骨架 7-bit hash、大小写/位置 8 个标志位、两侧标点类、数字桶；月份名单只在编译器里出现，模型完全靠拼写特征认识 "October"。行内不含邻居 token 的 hash，上下文由 five-tap 卷积和双向 scan 提供。
- **caller context 不进模型**。时区、夏令时、参考日期、展开上限全部由推理之后的 TypeScript 处理；模型只做 token 标注和边界切分。
- **backend 选择**：`auto` 在批次 ≥32 输入或 512 tokens 时走 WebGPU，否则 CPU（小输入时设备 dispatch 和 readback 开销占主导）；显式 `"webgpu"` 不回退 CPU，调用方自己处理无 WebGPU 和设备丢失。
- WebGPU 内核把 scan 按块并行处理，并携带精确块前缀，块边界不重置上下文；长输入用重叠窗口。
- 一万条输入的热中位数：WebGPU 122.4 ms，CPU 993.9 ms（architecture.md 记录）。

## 训练做法（architecture.md "Training and supervision"）

- 监督数据是生成的，不是爬的：`generate.py` 渲染 schedule，`natural.py` 加自然措辞家族和不含时间表达的负例散文；标签来自生成器自身结构，从不在模型自己的输出上训练。
- 真实英文语料靠 "harvest"：chrono-node 与自家 tagger 双教师一致才收（agreed 54.0k 行），另有 negatives、recurrence（chrono 不支持重复规则，只能用自家 tagger）、rescued、possessive、corrected、duration 各几百到几千行；agreed 之外的每一行都要通过编译验证，错误标注进不了语料。
- 西班牙语模型同构（38,745 参数），教师标注用了 Tatoeba、Amazon MASSIVE、Facebook MTOP 语料 + Sonnet 标注，编译器逐行校验。
- **negative flip 问题**：warm start 上微调新家族会破坏无关旧案例。解法是 focal distillation（Yan et al., CVPR 2021 的 Positive-Congruent Training）：`alpha=0, beta=5, lambda=0.1` 只约束参考模型已答对的 token，其余放开；alpha=1 时模型完全学不动。checkpoint 平均作为替代方案被测量过，两个方向都更差。
- **token 训练与序列评测的差距**：`--risk-lambda` 加 sequence-level 损失，只对解码错误的序列推高 gold path 分数（k=2 的 ranked-candidate loss，Edunov et al. NAACL 2018；Suzuki et al. COLING-ACL 2006）。scale 敏感：0.05 时英文 authored 集 71/71 但丢 5 个 chat 案例，0.005 时 70/71 多赢 3 个。
- 评测纪律：结构 holdout 和未见句式家族的评测分开（只 holdout 渲染字符串会泄漏短语家族）；评估 split 先于训练切出（曾修复 13.9% 的验证/训练重叠）。

## 导出检查与 provenance（MODEL_CARD.md "Reproducibility"）

- 导出时同轮构建候选与在产基线并比较 exact schedules：每个 gold 集合和家族必须保持原有数量，"池化提升"不能掩盖单一家族回退；保留载体必须改进或打平满分基线；`--force` 会跳过这些检查但留下记录（本次晋升未用）。
- `packages/training/active/` 存 export-report.json（权重 hash、lineage、校准、指标）、provenance.json（checkpoint 链与 hash 验证）、parity fixtures。干净 clone 能验证推理 parity（512 个 int6 vs PyTorch logits；浏览器 1,000 条英文 / 5,070 条西班牙语序列对真实 WebGPU），但无法复现完整训练（Git 不存 `.pt`）。

## 评测数字（MODEL_CARD.md，发布 checkpoint）

英文：

- 真实英文 holdout：5,869 / 6,011 exact schedules（97.6%），语料来自公开语料库且未进训练
- Authored 英文覆盖：77/77；chat gold 301/331（五轮晋升池化 591/625）
- 用户上报失败案例修复：26/37
- Microsoft Recognizers dev split：239/563（42.5%，策略差异计为失败）
- Chrono 对比集：76/85
- 非时间负例：188/192；token 准确率 validation 99.31% / heldout 98.87%

西班牙语：MASSIVE test split 741/787；Tatoeba holdout 173/179 等（详见 MODEL_CARD）。

性能对比（packages/benchmark/results/summary.json，Apple M4 Max，单条 "next Monday at 2pm" 热身 p50）：gpu-time CPU 约 0.15 ms。对比库的输出结构不同，作者自己声明这是时间对比、不是能力对比。

## 已知边界（MODEL_CARD.md "Limitations"，摘录）

- "in N units" 表 elapsed time 会被读成未来时间（"He ran a quarter mile in four minutes" 返回一个时间）。
- 1900–2059 的裸四位数字读作年份（`at 1930` 返回 1930 年）；1900 以下的四位年份可能读成时钟。
- 以星期命名的人名会被读成星期（"My friend Wednesday never answers her phone" 返回日期）。
- em dash 不支持（`13:20—15:50` 返回空）；en dash 走更弱的特征路径。
- 歧义数字日期跟随调用方 `dateOrder`，默认 MDY。
- 模糊表达（ASAP、after work、soon）按设计不给时钟值。
- 只有英文和西班牙文；其他语言可能错得没有诊断。真实用户措辞上的准确率未测量。
- 复杂重复例外能正确 preview 但返回 `unsupported-export` 诊断（单个 RFC 5545 规则表达不了）。
- 冷启动比 warm start 更会学语料但代价是丢 Chrono 对比分；种子波动约 1.85 个百分点，小于此的单次差异当噪音。
