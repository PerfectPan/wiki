# 页面时间冻结

## 摘要

可视化编辑工具最烦的一类问题是「要改的东西在动」：下拉菜单一失焦就收起、轮播图在轮、hover 态一移开就没、动画中途的样式抓不住。

常见解法是想办法**锁住元素**——监听 DOM 变化、元素消失后重新绑定。另一种解法是反过来：**把页面的时间停掉**。劫持浏览器的时间原语，页面里所有基于时间推进的动画和定时逻辑就一起停住，UI 变成静止的可检视对象。

这条笔记记录后者的实现方式，来源是 [[wiki/topics/product/Voila|Voila]] 扩展中一个 889 字节的注入脚本（`freeze.js`），见 `raw/sources/voila-extension-teardown-2026-08.md`。

## 原理

页面里的动效最终都落在三个时间原语上：

- `requestAnimationFrame`：CSS 之外的逐帧动画、大部分动画库
- `setTimeout`：延迟触发、自动关闭、过渡结束回调
- `setInterval`：轮播、轮询、跑马灯

把这三个函数替换掉，就拿到了页面时间的控制权。实现维护一个速度因子 `rate`（默认 `1`）：

| rate | 行为 |
| --- | --- |
| `1` | 直接透传原函数，零开销 |
| `0` | **冻结**：rAF 回调压入队列不执行；setTimeout 改为每 100ms 自旋重试；setInterval 直接跳过 |
| `0 < rate < 1` | **慢放**：setTimeout 延时除以 rate（拉长）；rAF 每 `max(1, round(1/rate))` 帧才放行一次 |

解冻时把冻结期间积压的 rAF 回调一次性 flush，动画从暂停处继续而不是丢帧跳跃。

参考实现的骨架（据 `freeze.js` 反混淆整理）：

```js
let rate = 1;
const rawRaf = window.requestAnimationFrame.bind(window);
const rawTimeout = window.setTimeout.bind(window);
const rawInterval = window.setInterval.bind(window);
const pending = [];
const stride = () => Math.max(1, Math.round(1 / rate));

window.requestAnimationFrame = (cb) => {
  if (rate === 1) return rawRaf(cb);              // 常态零开销
  if (rate === 0) return pending.push(cb), -1;    // 冻结：只入队
  let n = 0;                                       // 慢放：跳帧
  const tick = (t) => {
    if (rate === 0) return void pending.push(cb);
    ++n >= stride() ? cb(t) : rawRaf(tick);
  };
  return rawRaf(tick);
};

window.setTimeout = (fn, ms, ...args) => {
  if (typeof fn !== 'function') return rawTimeout(fn, ms);
  const d = (rate > 0 && rate < 1) ? ms / rate : ms;
  return rawTimeout(function self() {
    if (rate === 0) return void rawTimeout(self, 100);  // 冻结时自旋等待
    fn(...args);
  }, d);
};

window.setInterval = (fn, ms, ...args) => {
  if (typeof fn !== 'function') return rawInterval(fn, ms);
  let n = 0;
  return rawInterval(() => {
    if (rate !== 0 && ++n >= stride()) { n = 0; fn(...args); }
  }, ms);
};
```

## 落地要点

**必须在页面自己的 JS 世界里替换。** 浏览器扩展的隔离世界（isolated world）拿到的是另一份 global，改不到页面的 `window`。Voila 的做法是在 manifest 里给这个脚本单独声明 `"world": "MAIN"`。

**必须赶在页面脚本之前。** 任何库如果早于替换执行、并把原始 `requestAnimationFrame` 存进了自己的闭包，之后就绕过了劫持。所以注入时机是 `document_start`，不是 `document_idle`。

**需要一条跨世界的控制通道。** MAIN world 的脚本和扩展 UI 不共享内存。Voila 用 DOM 当信道：UI 侧把速度因子写到 `document.documentElement.dataset`，再派发一个自定义事件通知 MAIN world 读取。

**幂等守卫。** 用一个 global 标记避免重复注入导致多层包装（每层都会再套一次跳帧逻辑）。

## 它换来了什么

单独看，冻结只是「让页面停下来好检视」。但它真正解锁的是**逐帧调动画**：能停住、能慢放、能定位到动画的任意时刻，才谈得上在 GUI 里编排关键帧。

Voila 的关键帧编辑支持这批属性：`translate` / `scale` / `rotate` / `opacity` / `width` / `height` / `border-radius` / `background-color` / `color` / `border-color` / `filter`。时间冻结和关键帧编辑是同一套组合拳，不是两个独立功能。

## 局限

- 只能管住走时间原语的动效。**纯 CSS 的 `transition` 和 `animation` 不受影响**——它们由合成器驱动，不经过 JS。要停这部分得另外注入 `animation-play-state: paused` 之类的覆盖样式。
- 替换全局函数对页面有侵入性。常态（`rate === 1`）应直接透传原函数，避免给正常浏览带来额外开销。
- 冻结期间 setTimeout 走 100ms 自旋，本质是忙等；长时间冻结会累积一批待触发回调，解冻瞬间可能出现集中执行。

## 和「被动追踪」路线的对比

同一类问题的另一种解法是不干预时间，而是接受元素会变、变了再重新绑定。妙搭精调遇到的具体症状是 Antd Button 改 `type` 时组件内部走到 `Wave` 分支重建了 DOM，导致绑定的元素消失、工具栏被隐藏；解法是 `ResizeObserver` → `requestAnimationFrame` → 检查 `isConnected` → 用稳定标记属性 `querySelector` 重新绑定 → 重发坐标。

两条路线的取舍：

| | 主动冻结 | 被动追踪 |
| --- | --- | --- |
| 侵入性 | 高，替换页面全局函数 | 低，只在自己这侧观察 |
| 覆盖面 | 能停住所有 JS 驱动的动效 | 只处理「元素被替换」这一种症状 |
| 前提 | 能在页面脚本之前注入 MAIN world | 元素有稳定标记可供重新查找 |
| 额外收益 | 解锁逐帧动画编辑 | 无 |

对拥有预览容器的产品（例如自家 iframe 里跑用户产物），注入成本很低，两者可以叠加：用冻结解决「动着改不了」，用重绑解决「组件重建后丢引用」。
