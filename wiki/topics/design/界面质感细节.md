# 界面质感细节

## 摘要

Jakub Krehel（design engineer）的界面打磨清单，核心论点：**好界面很少来自单一决策，而是小细节的复利（compound）**。11 个细节可归为四组——文本、形状与边界、动效、对齐。每个细节都给了可直接执行的 CSS/Motion 值，属于「把品味拆成可验收规则」的实操版（与 [[Skill 工程化的产物协议范式]] 里「把主观判断变成可逐条检查的规则」的思路一致；作者后来也把它做成了 agent skill，见下文）。

## 文本

- **换行平衡**：标题用 `text-wrap: balance`（各行均匀分布），段落用 `text-wrap: pretty`（防末行孤字）；实践中**配对使用**——标题 balance、描述 pretty
- **文字发脆**：macOS 默认子像素抗渲染会让字偏重；`-webkit-font-smoothing: antialiased` 使字形更细更脆，加在整个 layout 上一次性生效
- **等宽数字**：数字刷新时跳动就用 `font-variant-numeric: tabular-nums`（Tailwind: `tabular-nums`）；注意 Inter 等字体在此属性下会改变数字造型

## 形状与边界

- **同心圆角（Concentric Radius）**：嵌套元素的圆角公式——**外圆角 = 内圆角 + padding**。作者称之为最容易被忽视、对质感影响最大的细节之一；大量产品至今圆角错配
- **阴影代边框**：三层 box-shadow 比实线 border 更有深度，且靠透明度适配任意背景（实色边框换背景就穿帮）：

  ```css
  box-shadow:
    0 0 0 1px rgba(0, 0, 0, 0.06),
    0 1px 2px -1px rgba(0, 0, 0, 0.06),
    0 2px 4px 0 rgba(0, 0, 0, 0.04);
  /* hover: 三层各加深至 0.08/0.08/0.06，transition-property: box-shadow */
  /* dark mode 退化为细环: 0 0 0 1px rgba(255, 255, 255, 0.08)，hover 0.12 */
  ```

- **图片描边**：图片加 `outline: 1px solid rgba(0,0,0,.1); outline-offset: -1px`（暗色用白色 10%），制造深度与一致的边缘；在 design system 里与其他元素的 border 语言保持统一

## 动效

- **图标语境动画**：图标状态切换（复制→对勾）时动画 `opacity`、`scale`、`blur`，让响应感更强；作者偏好 Motion（spring 易用），纯 CSS 亦可
- **动画必须可中断**：用户经常中途改变意图（菜单展开到一半想做别的）——不可中断的动画让界面「感觉坏了」，iOS 对此执行得非常普遍。经验法则：**CSS transition 朝最新状态重定向，适合交互；keyframes 时间线固定，适合一次性序列**
- **入场拆分 stagger**：入场动画通常是 `opacity + blur + translateY(8px)` 的组合；与其整块动画，不如拆成小块错峰——标题/描述/按钮逐块延迟 100ms，大标题可拆到逐词 80ms；参考时长 800ms `cubic-bezier(0.25, 0.46, 0.45, 0.94)`
- **退场要克制**：退场不应复制入场的注意力——要么滑出整屏（`calc(-100% - 4px)`，宽 + padding），要么只动 `opacity + blur(4px)` 不动位移；spring `duration: 0.45, bounce: 0`

## 对齐

- **光学对齐而非几何对齐**：按钮内「文字 + 图标」时，图标一侧的 padding 应略小；三角形、播放键等形状天然偏心。修复优先级：**直接在 SVG viewBox 里修 > 加 margin/padding**（图标库通常已处理一部分，但不是全部）
