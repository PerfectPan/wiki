## 产品定位（首页原文）

首页把产品拆成两层叙述：

1. **Delta, the app** — “Delta is a multiplayer environment for coding with agents. The unit of work is a thread: the conversation with an agent and the checkout of the repository it works in, kept together as one shareable artifact.”
2. **DeltaDB, the version control system** — “Where Git captures a snapshot at each commit, DeltaDB records work as a stream of fine-grained deltas. Each delta has a stable identity, so a reference anchors to a change rather than a line number and survives as the code moves.”

首页主标题：“Delta brings meaning back to your code”；副标题提到 “From the creators of Zed”。页脚版权为 “Zed Industries © 2026”，Terms/Privacy 直接指向 zed.dev。

首页营销区展示的能力（与文档一致的部分）：thread 内对话与改动同框、按行评论、模型选择器（示例显示 “Claude Fable 5”）、执行位置切换（示例显示 “Local Machine” / “Cloud”）。

## 核心对象（Core Concepts）

文档把三个概念与日常理解显式区分开：

- **thread**：与 agent 的对话；可独立存在，也可挂一个或多个 project。当一个 thread 挂上 project，它**同时持有它改动过的文件的工作副本**，“The conversation and file changes are recorded together, in order.” 四条性质：持久、可并行（默认各自隔离副本）、可整体回退（“The conversation and the thread’s project files rewind together”）、可共享（协作者实时看到同一份对话与文件）。
- **project**：你打开的文件夹，两个约束——“The folder must be the top-level folder of a Git repository.”；Delta 把 “every file Git tracks, plus untracked files Git does not ignore” 导入 DeltaDB。
- **Delta worktree**：thread 在某个 project 上的工作副本，其历史记在 DeltaDB 里，“A thread has one Delta worktree per project it works on.” 文档特别声明这不是 git worktree：“A Delta worktree is a different thing: the shared project history that Delta replicates between participants.”

关系链（文档原文即为此结构）：`thread → (works with) project → Delta worktree (recorded in DeltaDB) → (mounted on desktop) checkout`。默认配置叫 **Isolated Workspace**。

## DeltaDB 与 delta 语义（Delta & Git）

- “DeltaDB is the shared database behind a Delta thread. It records thread messages, comments, Delta worktree changes, and file edits as deltas.”
- **delta** 的定义：“a delta is a recorded change to a thread or Delta worktree. It can represent a file edit, a change to the file tree, a message, a comment, or another update to shared state. Each delta records who made the change and where it belongs in the thread’s history.”
- 与 commit 的差别（原文）：“Unlike a git commit, a delta is created continuously as work happens. You do not need to stage or commit it.” 以及 “Git records a snapshot of the repository each time someone commits. DeltaDB records each edit, from each person and the agent, in the order it is made.”
- 每个连接的客户端各持一份数据库副本，Delta 负责保持同步（“Each connected Delta client holds a copy of the database, and Delta keeps the copies in sync”）。
- 文件有两种表示：DeltaDB 里的共享表示，以及落在磁盘上的 checkout。“Agents can read and edit a Delta worktree’s shared file representation in DeltaDB. On desktop machines, Delta can also materialize those files in folders called checkouts.” 浏览器参与者与浏览器侧 agent 直接用复制出来的文件表示，没有 checkout。
- **git 的关系是“引导同步”**：worktrees 页明确 “Delta currently uses git as a way to bootstrap our syncing”，且只支持配置了 origin 的仓库。
- 导入范围：Git 跟踪的文件（**包括已被 ignore 规则匹配、但仍被跟踪的文件**）、跟踪文件的未提交改动、未被 ignore 的未跟踪文件。被 ignore 的未跟踪文件不进 DeltaDB、不参与同步。文档给了 WARNING：“Adding a path to `.gitignore` does not protect a file Git already tracks.”
- 行尾处理：写 checkout 时保留每个文件的行尾，并遵守 `core.autocrlf`、`core.eol`、`.gitattributes`，以免 CRLF 仓库在 `git status` 里显示全量修改。
- **Jujutsu**：对 colocated 模式的 jj 仓库有早期支持（`.git` 与 `.jj` 同目录），会在每个托管 checkout 里跑 `jj git init --colocate`；托管 checkout 归档时会保留 jj 的 operation log，重新挂载时恢复。文档自称 “Jujutsu support remains incomplete.”

## Checkout、git remote 与工作回流（Delta Worktrees / Delta & Git / Review & Sync）

- thread 里每个参与者在**各自机器**上有一份 checkout。“When you send a message, the agent runs on your machine using your checkout. When a collaborator sends a message, the agent runs on their machine using their checkout.”
- checkout 由 Delta 托管：thread 归档时从磁盘移除，重开时按需重建（前提是记录下来的 worktree 历史还在）。托管 checkout 位置：若本机有连接的 clone，则嵌在该 clone 的 `.delta` 目录下；否则在完全托管的目录里。
- **两个 git remote**：
  - `origin`：你仓库原本指向的共享上游（如 GitHub）。让 agent 发布分支或开 PR 时默认推到它。
  - `local`：你本机自己的仓库。agent 可以把分支推到 `local`，不经过 GitHub 就把工作交给你；推你当前检出的分支时，干净的工作树会就地更新。
  - 队友机器上（没有该 project）：`origin` 相同，`local` 指向 Delta 自己克隆的仓库。
- 工作回到你手上的四条路径：**in place**（thread 采用你自己的 project 目录作为 checkout）、**through local**、**through origin**、**from the checkout**（托管 checkout 是真实文件夹，可用 Zed 打开、构建、拷出文件）。
- 托管 checkout 有自己的 git 仓库，agent 的 commit 落在那里，**不是**你的 project 目录；“Committing is not the step that brings work to you; pushing to local or your source remote is.”
- `Changes` 标签页提供四种比较基准：Branch base（如 `origin/main`）、Last Commit、Last Turn、从 thread 打开的某个 commit。分支 diff 的 merge base 会同步给协作者，保证大家比的是同一个 base。
- **Review thread** 是附在产出工作的 thread 上的独立对话，用来“像 reviewer 一样读改动并给出结论”。它包含 agent 生成的 **change guide**（按最能解释清楚改动的方式排序的结构化走查，而不是按文件罗列）；给出 Approve / Request Changes 的 verdict 后会回写到父 thread，父 thread 头部 reviewer 头像上显示徽章。review agent 在**分叉出来的** Delta worktree 里工作，改动不回写父 thread；要把 review 的改动带回来，点 verdict 上的 `Pull Changes`（拉起的是那次 verdict 保存的快照）。
- **Land changes**：桌面端用 `Land Changes From This Thread`（浏览器不可用）。它会开一个专门的 Land subthread 跑你项目里的 landing workflow：有 1 个合格 skill 就直接跑，有多个就列出来让你选（不记住默认），没有就提议建一个并要你批准后才写。“The skill defines your checks, merge strategy, and publication steps; the button does not prescribe a Git workflow.”

## Agent 侧的能力面

**Subagents**（`/docs/agents/subagents`）：

- 三个内置 profile：**Worker**（实现改动，完整工具权限）、**Scout**（从代码库或网上收集信息）、**Reviewer**（检查已有改动）。
- 文件访问语义：Worker 与 Reviewer 默认使用父 thread Delta worktree 的**隔离副本**，成功完成后自动合并回来，失败的隔离工作不合并；**Scout 直接用父 thread 的 checkout，它的改动立刻生效**。文档警告：“Scout and Reviewer do not have file-editing tools, but both can change files through terminal commands. Don't treat either profile as read-only.”
- 并发默认值（settings 页）：每父 thread 最多 4 个并发 subagent，整个 Delta 进程最多 8 个；两项都可设为 0 以暂停。
- 默认 `allow_parent_model_override` 为开，即父 agent 可以覆盖 profile 指定的模型。
- profile 是 **TOML 文件**，放在 settings.json 旁的 `profiles` 目录里；可自定义 `prompt`（追加）或 `system_prompt` / `system_prompt_file`（替换基础 prompt，两者不能同时设）；`worktree = "isolated" | "shared"` 控制文件访问。profile 是**机器本地**的，共享 thread 不会把自定义 profile 带到别人机器上。
- 模型选择顺序：provider 专属选择 → profile 默认 → Delta 内置默认。Worker 默认跟随父 thread 的模型。

**Skills**（`/docs/agents/skills`）：

- 技能是 Markdown 文件 + YAML frontmatter，字段为 `name`、`description`，可选 `user-invocable`（默认 true，决定是否出现在 composer 的 `/` 菜单）与 `disable-model-invocation`（默认 false，为 true 时 agent 不能自行加载）。
- 位置：项目技能在仓库的 `.agents/skills/`，个人技能在 `~/.agents/skills/`，常见布局 `.agents/skills/<name>/SKILL.md`，也支持嵌套分类目录；只用在本地的技能可放 `.delta/skills/`。**项目技能与个人技能同名时项目技能胜出**。
- 内置技能：`/change-guide`；另外 agent 可以自行搜索你的其它 thread 取上下文。`@Delta` 用于询问 Delta 自身的用法。
- 内置斜杠命令：`/compact`、`/model`、`/thinking`、`/fast`、`/add-project`、`/subthread`、`/review`。

**Terminals**：在 composer 空行起始输入 `!` 打开交互终端，终端在 thread 的 checkout 里启动。agent 自己的命令不使用你的交互终端，也不使用 Default Shell：macOS/Linux 上是 `/bin/sh`，Windows 上是 Git Bash（POSIX 命令）与 PowerShell 两套工具。装了 direnv 且 checkout 有 `.envrc` 时，Delta 会为交互终端与 agent 命令加载它，**direnv 未批准过的 `.envrc` 由 Delta 代为授权**。

**Models & Providers**：三种接法——自己的 API key（Anthropic、OpenAI、OpenRouter、OpenCode Zen、OpenCode Go）、已有订阅（ChatGPT Plus/Pro、GitHub Copilot、Grok）、hosted models（随 Zed 付费计划，按 token 计费）。key 也可放 `~/.config/delta/.env`（Windows 为 `%USERPROFILE%\.config\delta\.env`），已导出的环境变量优先。thread 可以中途换模型，对话与 worktree 继续。自动 fallback 的例子写在文档里：某请求被 “Claude Fable 5” 拒绝时切到 “Claude Opus 5” 继续，并给出通知。

**Thread 的其它语义**（`/docs/agents/threads`）：subthread（`Cmd+Shift+Enter`，继承父对话但不自动合并改动）、编辑已发消息（其后的回复会被丢弃）、`Revert Conversation to Cursor`（对话与仍匹配该点的 worktree 一起回退）、@ 提及文件/目录、thread 内搜索。归档不删除内容；**归档或最后打开三天后，Delta 会删除该 thread 的本地历史**（服务端已有完整副本），重开时重新下载，所以老的归档 thread 需要联网才能打开。

## 协作（Collaborate in a Thread / Delta on the Web）

- 共享权限三档：Only people invited / Everyone at organization / Anyone with the link；默认 Private，可由 `Default Visibility` 改成组织内自动共享。只有 owner 能改权限，所有人可见权限与成员列表。文档对 link 共享给了 WARNING：链接可被转发，登录后即可访问该 thread 及其引用的 project。
- 邮件邀请一次最多 10 人，邀请 14 天后过期，被邀请者以 editor 身份加入。
- **草稿是共享的**：每个人各自起草、带作者属性，别人能看到正在输入的草稿；“When someone sends, all pending drafts at the end of the thread are submitted together”，agent 一个 turn 回应所有作者的消息，费用记在发送者身上——“Model usage belongs to whoever sends the request, not the thread’s owner.” 文档还提示：“There is no way to send a message to collaborators only.”
- **agent 在发送者所在的环境里跑**：“An agent turn runs wherever the sender is using Delta, not on the thread owner’s device or another participant's device.”
- **执行环境差异**（Delta on the Web）：浏览器 turn 用 Delta 托管的模型，**没有磁盘 checkout、没有 shell**，不能用终端命令；要用本机的工具、凭据、进程，必须在桌面端跑。桌面端可以挂 checkout、用已装工具、环境变量、凭据、网络、正在运行的进程；“Delta syncs the conversation and recorded file changes, but it does not sync machine-local runtime state.”
- 浏览器可以读 thread 的文件与 diff（不用 clone），可以发消息、加评论、提交 review verdict。创建并共享新的 top-level thread、管理 project 要用桌面端。
- 每个人用自己的 provider 解析 thread 选的模型；如果你没有协作者用的那个 provider，Delta 会找一个你有的等价模型，否则标记为不可用（你仍可读与评论，发送前需先选一个可用模型）。

## 数据、隐私与安全

**数据存放**（`/docs/privacy-and-security/data-storage`）：后端整体在 Cloudflare。

| 数据 | 位置 |
| --- | --- |
| 文件内容、git commit、history packs、checkpoints | Cloudflare R2 |
| 用于实时同步的 thread 与 Delta worktree deltas | Cloudflare Durable Objects（背后是 SQLite） |
| thread、仓库、协作者、账号元数据 | Cloudflare KV 与 D1 |

服务端保存四类东西：仓库内容与历史（含 commit 与文件内容）、thread 的 deltas、元数据（可分享 thread 记录与加入密钥、账号的 thread 目录、配置的 git remote URL 与派生仓库名、协作者 GitHub login、commit 作者/提交者身份与提交信息）、订阅凭据（ChatGPT/Grok 的 OAuth grant 存在 Zed Cloud，Copilot 凭据留操作系统 keychain）。文档提示 “Avoid remotes that embed credentials.”（因为 remote URL 会被存）。

**加密**：传输 TLS；静态由 Cloudflare 托管密钥加密（R2、Durable Objects、KV、D1）。

**Secret redaction**（`/docs/privacy-and-security/security`）：本地发现密钥值，在“存储、同步或发给模型供应商之前”替换为 `[REDACTED]`，只把占位符与 redaction 元数据发出去。发现来源包括：名字含 token/secret/key/password 的环境变量、按长度与熵判断像凭据的环境变量值、`.env` 及变体、mise 配置（`mise.toml` / `.mise.toml` 等）、home 目录下的凭据文件（SSH 私钥、云与容器凭据、包管理器配置、开发工具凭据）、启动时短暂执行凭据 helper（kubectl、gh、glab、aws、gcloud、az、heroku、fly）、以及按格式识别的已知凭据（GitHub、npm、Google、GitLab、Stripe、PyPI、OpenAI、Anthropic、Slack）。长度下限：8 字符，纯数字 12，仅凭形状识别的 16。**限制**：不扫描任意文件找凭据；名字不寻常、太短或低熵的凭据可能漏掉。

**发给模型的内容**（`/docs/privacy-and-security/privacy`）：请求可包含对话历史、协作者的消息与评论、附带图片、工具调用与结果、终端或命令输出、agent 读到的文件内容；agent 还有个工具可以**搜索你的其它 thread 并读取其记录**（以有界摘录形式），当前 thread 被排除在该工具之外。“Delta does not automatically send every file in the repository.” hosted model 的请求经 Zed Cloud，自接 provider 的请求直连 provider（ChatGPT/Grok 订阅下 Zed Cloud 只存 OAuth grant、发短期 token）。“Delta does not use your code or conversations to train AI models.”

**Agentic safety（现状，原文强调）**：

- 页面开头：“Delta is in early access and does not yet have the agent safeguards described below. Use Delta with care. Early-access use is at your own risk and subject to Delta's Early Access Agreement.”
- “Delta does not have an agent permission system. Based on your instructions, the agent acts autonomously and does not ask before calling tools. This includes potentially destructive calls.”
- “Delta does not sandbox agents. An agent has unrestricted access to the device where it runs.”
- worktree trust：“Delta does not ask you to review settings or configuration in a shared repository or Delta worktree before loading them.” 会自动执行的东西：可执行的 `.agents/prepare`（或 `.delta/prepare` 覆盖）在首次挂载托管 checkout 时运行（采用既有 checkout 时跳过）；macOS/Linux 上适用于 checkout 的 `.envrc` 经 direnv 生效，且“Delta allows it if direnv has not seen it before”；`AGENTS.md` 与 `.agents/skills/`、`.delta/skills/` 下的技能会变成 agent 的指令。
- “Agent permissions, sandboxing, and Delta worktree trust controls are on the roadmap.”

**其它身份侧事实**：使用需要 Zed 账号（`/docs/account/authenticate`）；`@Delta` 之外没有别的入口说明。启动时会与 Zed 服务器核对——troubleshooting 页写明 “Delta checks in with Zed's servers at launch: you need to be signed in, have access to the Delta beta, and be online for Delta to open a workspace.”

## 定价（/pricing 与 /docs/account/plans-and-pricing）

- **Personal $0**：“Use your existing API keys or external agents with Delta.” 列出的能力是回退到任意编辑、看到每个改动背后的对话、在上下文里审阅与反馈、与队友和 agent 一起写。
- **Pro $10/月**：“Zed-hosted models, available out of the box.”，每月含 $5 tokens，超出按用量计费，包含 Personal 的能力。
- **Business**：面向需要集中控制的团队；FAQ 写明 “When you use Delta with a Zed Business organization selected, that organization's server-enforced data and privacy controls apply in Delta.”
- 计划与 Zed 共用账号与额度：“If you already have a Zed subscription, it covers Delta.”；**edit predictions 不在 Delta 提供**（pricing FAQ 与 plans 页都提到）。
- Pro 试用两周，“includes $5 in GPT-5.6 Luna credits”，余额在 Zed 与 Delta 之间共享，不需要信用卡。

## 路线图（/roadmap）

写明 “Delta is in beta. This roadmap covers what we're building for public beta and general availability. Scope and sequencing may change as the work develops.”

**Now（5 项，均 In Progress）**：Delta on the web（把更多桌面体验搬到 web，含项目组织、thread 导航、代码审阅）；Repository-based access（用 GitHub 仓库既有权限控制共享 thread 的访问）；Remote runtime（在持久化云开发环境里跑 agent，activity 与改动同步回 thread）；**Claude Code plugin**（“Track Claude Code conversations and code changes in DeltaDB, then review them in Delta or on delta.dev”）；MCP support（通过 Model Context Protocol 连外部工具与数据源）。

**Next（6 项，均 Up Next）**：@mentions、repository-level context（跨仓库所有 worktree 访问评论与对话）、**sandboxing**（“Run agents in isolated environments, with control over what each agent can access”）、WSL 支持、conversation branching、graph view。

## 官方 troubleshooting 里记录的真实故障模式

- macOS 隔离标志导致每次都提示移动到 Applications（需 `xattr -dr com.apple.quarantine`）。
- **需要 Xcode 许可证**：页面 “Delta asks me to accept the Xcode license”——Delta 需要 Git 来准备 worktree，未接受的许可证会让 Git 跑不起来。
- worktree 历史不可用：`Failed to prepare the … Delta worktree`，对话还在但 checkout 建不出来；重试不会找回仍然缺失的历史，只能 Remove Project 再 Add Project（且不会恢复被移除 worktree 的已记录状态）。
- “I opened the same branch, but my earlier changes are missing”：每个托管 checkout 有自己的 git 仓库，同名分支不会带过来未提交的改动与未推送的 commit。
- “The agent committed, but my repository doesn't have the changes”：托管 checkout 在 `.delta/worktrees/` 下、有自己的 git 仓库，要 push 到 local remote 才会出现。
- **同步分叉**：“This thread has diverged from the server”——Delta 会保留未同步的本地改动，生成一个名为 `<thread name> (local changes)` 的恢复副本供你选择 `Keep Local Changes in a New Thread` 或 `Discard Local Changes`；若不满足条件还会给出 `Fork & Restore`。
- 协议版本不匹配（需重启更新）、本地数据由更新版本写入（需 `Check for Updates`）、同时只允许一个应用实例。

### Software Is Made Between Commits（2026-06-11，DeltaDB 公开）

- “DeltaDB breaks your work into a stream of fine-grained deltas. Where Git captures a snapshot at each commit, DeltaDB captures every operation in between and gives each one a stable identity.”
- **“Because DeltaDB embeds conflict-free replicated worktrees, many people and agents can edit the same files at once across different machines.”**
- “A message and the edit it produced are recorded side by side, so neither drifts away from the other.”
- “The files are real: agents work in them through a terminal, and you can mount the whole worktree to disk whenever you want your own tools on it.”
- 定位：“Git and CI stay for what they're good at: running checks and connecting you to the rest of the world, rather than being the place collaboration is forced to happen.”
- 背景：作者自述从 2021 年创立 Zed 起就想摆脱 commit 的约束（“our plan was to build an editor worthy of the world's best developers, then offer a better way to work together inside it”）。

### Introducing Delta（2026-08-12，private beta）

- “Delta is the second half of a plan we've been executing for years: to build the best place to write code, then make it the best place to talk about code.”
- **为什么是独立应用而不是 Zed 的功能**：“We could have added DeltaDB to Zed, and eventually we will. But the best possible experience required an entirely new kind of application.” 以及 “rebuilding Zed's foundations underneath hundreds of thousands of daily users would have meant disrupting the workflows they rely on every day”；“DeltaDB will come to it, but Delta is where it begins.”
- 与 git 的关系：“DeltaDB works with the git repository you already have. Every edit and conversation is captured between your commits. You can commit and push like you always did, and teammates who never open Delta see a normal git repo.”
- 评论的锚定：“On a commit-based platform, comments attach to snapshots and fall out of date as soon as the code changes.” Delta 里评论可以锚在任何位置（对话、diff 的某一行、计划的一步、thinking block）。
- **云端执行**：“Move your work to a cloud runner, close your laptop, and the agent keeps going while its conversation and code stay synchronized with the thread.”（这解释了首页那个 Local / Cloud 切换）
- **Web 是同一个应用**：“Delta.dev isn't a second-class version of Delta built in JavaScript and HTML. We wanted to bring you the same Rust application, compiled to WebAssembly and rendered through WebGL.”
- **第三方 harness**：“Delta also connects to third-party agent harnesses, starting with Claude Code. Keep working in the terminal you already use, and your session syncs live into a Delta thread.”（截至抓取日，delta.dev 的 26 个文档页里没有任何 Claude Code 相关内容，这一条只在博客里出现）
- 界面取向：“diffs open in full, transcripts stay whole”（不折叠、不截断、不摘要）；“the conversation is a document, and your cursor works everywhere in it”。

### Xanadu Was Waiting for Agents（2026-09-01，数据模型与设计依据）

这篇是理解 DeltaDB 数据结构的关键，讲的是「依赖树」：

- 命名：**Lamport timestamp（1978）**——“Every operation by every human and agent is named by an actor plus a Lamport timestamp, forever.”
- 状态标识：**Merkle tree / Git（1979 / 2005）**——“DeltaDB names every state between commits by the Git commit it descends from and the set of actor-and-timestamp delta IDs applied above it.”
- 收敛：**CRDT（2011 形式化，作者称是 Zed 自己过去十年的核心工作）**——“A Delta worktree can be edited by several people and agents on different continents at once.”
- 存储：“We keep every version of everything by default.”
- 复制：“Every thread is live, replicated data on every participant's machine and in the browser.”
- **云端机器**：**Firecracker 级 microVM**——“Agents in Delta can provision a new isolated cloud machine mid-conversation.”
- 渲染：Tree-sitter + GPUI——“A Delta thread is a live projection of its permanent structured history, recomputed rather than stored as a flattened document.”
- **文件在底层的表示是「有稳定身份的 fragment」，不是字符数组**：“On screen, a file still looks like a one-dimensional string of characters but underneath, DeltaDB represents it as fragments with stable identities. Those identities let us create anchors... A line number can express where text appears in one snapshot, while an anchor preserves which span we mean across snapshots.”
- 因果元数据：“By preserving the causal metadata beneath that surface representation, like which operation produced each fragment and what prior state it built on...”
- 互操作立场（对照 Xanadu 的失败）：“We'll work with the git repository you already have. Every thread is also a git branch, so teammates who never open Delta see a normal repo”；并且“You can keep mirroring your repo to GitHub to work with anyone who isn't ready to make the switch”。
- Xanadu 的两条规则被引为设计目标：“Never copy, always reference”（transclusion）与“Never overwrite, always version”；作者的一句话总结是 “the session and the record are the same object”。

### Replace PRs with Delta – Now in Public Beta（2026-09-16，public beta）

- “Last week, we crossed a key milestone: **we disabled pull requests on Delta's own repository.** We now build and collaborate on Delta entirely within Delta.”
- 数据点：“33 of us have landed **570 changes to main** since we turned off pull requests.”
- **定价表述**：“During the public beta, Delta is free. We'll introduce paid plans soon for individuals and teams. **There will always be a free version of Delta.**”——与 `/pricing` 页当前展示的 Personal $0 / Pro $10 每月（含两周试用、$5 tokens）**不一致**，需要标注。
- 审阅模型：review 有自己的隔离 worktree 副本，review 里用 agent 探索或修改不影响原工作；修复可以并入父 thread 再 land。
- 迁移路径：“You don't have to move your whole team into Delta”；`zed-industries/zed` 暂时留在 GitHub，鼓励贡献者「把 Delta thread 和 PR 一起分享」。
- 野心：“We believe that threads will be the new fundamental unit of software development, and the best way to model their state is with deltas.”；“Pull requests are the first part of the GitHub workflow we're leaving behind”；后续方向包括「Git storage in DeltaDB」与「content-based builds could bring CI-style verification directly into the thread」（当前是让 agent 触发既有 CI 并检查结果再 land）。
- 可用范围：macOS / Linux / Windows 下载，web 免安装，手机浏览器可以跟进 thread。
